# Meta広告（Instagram）でウェイティングリストを集めるLP実装

**日付**: 2026-05-27  
**会話の概要**: WorldClass の LP（https://worldclassjp.netlify.app/）に Instagram/Meta 広告を出すための計測基盤を整備した。Meta Pixel の設置・OGP タグの追加・UTM パラメーターのキャプチャ・学年フィールドの追加・希少性バッジの追加を行った。

---

## 今日学んだ概念

### Meta Pixel（メタピクセル）
- **何か**: Meta（Facebook/Instagram）が提供するトラッキング用スクリプト。LPの `<head>` に1〜2行貼るだけで動く
- **なぜ必要か**: 「広告を見て何人がLPに来て、何人が登録したか」を Meta 広告マネージャーに送信するため。これがないと広告の費用対効果が全くわからない
- **例え**: 飲食店のクーポンを配って「何人がそのクーポンを使ったか」を集計するシステム。クーポン（広告）と入口の台帳（Pixel）がセットで初めて効果測定できる

### Lead イベント（fbq track Lead）
- **何か**: フォーム送信が完了したとき Meta に「1件リード獲得」と通知する JavaScript の1行
- **なぜ必要か**: Meta の広告最適化（Learning Phase）は「どんな人が登録したか」のデータを学習して、似た人に広告を出すようになる。このイベントを送らないと学習が進まず、広告の精度が上がらない
- **例え**: 塾に「この広告を見て来ました」と言ってもらうアンケート。言ってもらうほど塾はどの広告が効いているか学習できる

### OGP（Open Graph Protocol）
- **何か**: SNSやメッセージアプリでURLをシェアしたときに表示される「カード（タイトル・説明・サムネイル）」を制御するHTMLの `<meta>` タグ群
- **なぜ必要か**: 広告の「リンク先プレビュー」として表示される。OGPがないとURLの文字列がそのまま表示され、クリックされにくくなる
- **例え**: 商品のパッケージデザイン。中身（LP）が良くても、パッケージ（OGPカード）がダサいと手に取ってもらえない

### UTMパラメーター
- **何か**: URLの末尾に `?utm_source=instagram&utm_medium=paid_social` のように付け足す文字列。どこから来たかを識別するタグ
- **なぜ必要か**: 「Instagram広告A」「Instagram広告B」「X（Twitter）からの自然流入」など、流入元ごとに登録数を比較できる。これがないと「どの広告が効いたか」が判断できない
- **例え**: 宅配便の伝票番号。荷物（ユーザー）がどの経路（広告・SNS・検索）を通って来たか追跡できる

### 希少性・先行者利益の訴求
- **何か**: 「先着300名限定」「今だけ」などの文言でユーザーに「今すぐ行動しないと損する」と感じさせるUIデザイン
- **なぜ必要か**: 広告から来たユーザーは「また今度でいいか」と離脱しやすい。希少性を示すことで登録のハードルを下げる（CVR向上）
- **例え**: コンビニの「本日限定」シール。「別に今日じゃなくていいか」を「今日買わないと」に変える

### Meta Pixel の設置（index.html）

```html
<!-- index.html の <head> 内、他の <script> より前に置く -->
<script>
!function(f,b,e,v,n,t,s)
{if(f.fbq)return;n=f.fbq=function(){n.callMethod?
n.callMethod.apply(n,arguments):n.queue.push(arguments)};
if(!f._fbq)f._fbq=n;n.push=n;n.loaded=!0;n.version='2.0';
n.queue=[];t=b.createElement(e);t.async=!0;
t.src=v;s=b.getElementsByTagName(e)[0];
s.parentNode.insertBefore(t,s)}(window,document,'script',
'https://connect.facebook.net/en_US/fbevents.js');
fbq('init', 'YOUR_PIXEL_ID_HERE'); // ← 15桁の数字に差し替える
fbq('track', 'PageView');          // ← ページを開いたときに自動発火
</script>
<noscript>
  <img height="1" width="1" style="display:none"
    src="https://www.facebook.com/tr?id=YOUR_PIXEL_ID_HERE&ev=PageView&noscript=1"/>
</noscript>
```

**ポイント解説:**
- `fbq('init', 'PIXEL_ID')`: PixelをこのサイトのIDで初期化する。1ページに1回だけ呼ぶ
- `fbq('track', 'PageView')`: LP が読み込まれた瞬間に「1閲覧」として Meta に送信される
- `<noscript>` の `<img>`: JavaScript が無効なブラウザ向けのフォールバック。1×1ピクセルの透明画像を読み込むことで計測する

### Lead イベントの発火（app.jsx）

```jsx
// フォーム送信が成功したとき（res.ok の中）
if (res.ok) {
  setSubmitted(true);
  // Meta Pixel Lead イベント発火（広告最適化に必須）
  if (typeof window.fbq !== "undefined") {
    window.fbq("track", "Lead");
  }
}
```

**ポイント解説:**
- `typeof window.fbq !== "undefined"`: Pixelがブロックされている（広告ブロッカー等）場合にエラーにならないための安全確認
- `"Lead"`: Meta が定義している標準イベント名。これを使うと広告マネージャーで「リード数」として自動集計される

### UTMパラメーターのキャプチャ（app.jsx）

```jsx
const [utmData, setUtmData] = React.useState({});

// コンポーネントがマウントされたとき1回だけ実行
React.useEffect(() => {
  const p = new URLSearchParams(window.location.search);
  setUtmData({
    utm_source: p.get("utm_source") || "",    // 例: "instagram"
    utm_medium: p.get("utm_medium") || "",    // 例: "paid_social"
    utm_campaign: p.get("utm_campaign") || "", // 例: "waitlist_test_w1"
    utm_content: p.get("utm_content") || "",  // 例: "reels_angle_a"
    utm_term: p.get("utm_term") || "",
  });
}, []); // [] = 初回のみ実行（依存配列が空）

// Formspree 送信時にスプレッド構文で混ぜる
body: JSON.stringify({
  email: email.trim(),
  userType,
  ...utmData, // ← UTMデータを全フィールドとして展開
  _subject: `[WorldClass] ウェイティングリスト新規登録: ${email.trim()}`,
}),
```

**ポイント解説:**
- `URLSearchParams`: URLの `?` 以降のパラメーターを扱う組み込みクラス。`p.get("utm_source")` で `utm_source` の値を取得
- `|| ""`: パラメーターがなかったとき `null` ではなく空文字にする（Formspreeに `null` を送らないため）
- `...utmData`: スプレッド構文。オブジェクトのプロパティを全部展開して混ぜる。`{a:1, ...{b:2}}` → `{a:1, b:2}`

### 学年フィールド（ご家庭のみ表示）（app.jsx）

```jsx
const gradeOptions = ["幼児・未就学", "小1〜3年", "小4〜6年", "中学生", "高校生以上"];

// JSX：userType が「ご家庭」のときだけレンダリング
{userType === "ご家庭" && (
  <div className="field-group">
    <label className="field-label">
      お子さんの学年<span className="req">*</span>
    </label>
    <div className="chip-row">
      {gradeOptions.map((g) => (
        <span
          key={g}
          className={`chip ${grade === g ? "active" : ""}`}
          onClick={() => setGrade(g)}
        >
          {g}
        </span>
      ))}
    </div>
  </div>
)}
```

**ポイント解説:**
- `userType === "ご家庭" && (...)`: 短絡評価（ショートサーキット）。左が `false` なら右は評価（描画）されない。条件付きレンダリングの最も一般的な書き方
- `grade === g ? "active" : ""`: 三項演算子。選択中の選択肢にだけ `active` クラスを付けてハイライト
- 利用者区分変更時に `setGrade("")` でリセットしている（例: 「ご家庭」→「個人塾」に変えたとき学年が残らないように）

## なぜそう書くか（設計の理由）

- **Pixel ID をプレースホルダーにした理由**: 広告アカウントを作る前にコードを書いているため。`YOUR_PIXEL_ID_HERE` という文字列にしておくことで「差し替え忘れ」に気付きやすくする
- **学年フィールドを「ご家庭」のときだけ表示した理由**: 個人塾・公民館などの法人ユーザーには子どもの学年という概念が不自然。フォームの項目が増えると CVR（登録完了率）が下がるため、不要な人には見せない
- **`typeof window.fbq !== "undefined"` のチェック**: 広告ブロッカーやSSR環境でPixelが読み込まれていないとき `fbq is not defined` エラーが出てフォーム全体が壊れるのを防ぐ防御的プログラミング
- **UTMをサーバー（Formspree）に送る理由**: ブラウザ上だけに持つと「どの広告経由か」を後から集計できない。フォームデータとして保存することで、登録者の流入元をCSVで分析できる
